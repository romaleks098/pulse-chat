## 2. Архитектура проекта

- **Клиент (`client/`)**:
  - React 19, TypeScript, Vite, Tailwind CSS, Lucide Icons.
  - Управление состоянием: `ChatContext.tsx`, `ThemeContext.tsx`, `CallContext.tsx`.
  - Дизайн-токены: CSS-переменные на `:root` (поверхности, текст, пузыри, акцент, радиусы, шрифты, плотности).
  - Базовые UI-примитивы (`client/src/components/ui/`): `Avatar`, `Badge`, `ContextMenu`, `Modal`, `Tabs`, `Toast`, `Slider`, `ColorPicker`.
- **Сервер (`server/`)**:
  - Node.js, Express, TypeScript, Socket.io, Multer, better-sqlite3 (локально) / pg (в проде).
  - Маршруты: `/api/auth`, `/api/conversations`, `/api/messages`, `/api/health`, `/api/sync`.
  - Защита: OAuth 2.0 PKCE со state в БД, `timingSafeEqual` для Telegram Webhook, HttpOnly cookies.
- **Интеграция с мобильными платформами**:
  - Capacitor Android SDK (`client/android`), PWA Manifest, Service Worker.

## 4. Хронология всех версий и решённых проблем

### Версия 1.9.2
**Дата:** 24 октября 2026  
**Категория:** Mobile UX / Safe Area / Security & PKCE OAuth / Media Storage Persistence / UI Cleanliness  
**Статус:** Релиз v1.9.2: Устранение перекрытия статус-баром в Android, устранение ошибки PKCE при входе через Google в приложениях, сохранение медиафайлов в БД PostgreSQL/SQLite, скрытие кнопки GitHub  

#### 1. Устранение наложения системного статус-бара Android на шапку приложения:
- **Проблема:** В `.apk` на Android верхняя часть интерфейса (бургер-меню, аватар, кнопка «Назад», название чата, статус) залезала прямо под системный статус-бар Android (часы, процент батареи, вырез/камеру), делая нажатия на элементы практически невозможными.
- **Корневая причина:** На Android 15 (API 35) система принудительно включает режим Edge-to-Edge (`fitsSystemWindows: false`), а в WebView CSS-переменная `env(safe-area-inset-top)` часто возвращает `0px`.
- **Исправление:**
  - В `client/android/app/src/main/res/values/styles.xml` установлены флаги: `android:fitsSystemWindows = true`, `android:windowOptOutEdgeToEdgeEnforcement = true`, задан тёмный цвет фона статус-бара `android:statusBarColor = #090d16`.
  - В `client/capacitor.config.json` настроен плагин `@capacitor/status-bar`: `overlaysWebView: false`, `backgroundColor: "#090d16"`, `style: "DARK"`.
  - Установлен пакет `@capacitor/status-bar` в `client`.
  - В `client/src/index.css` введены системные отступы `--safe-top: max(env(safe-area-inset-top, 0px), 0px)` и для класса `.capacitor-android`: `--safe-top: max(env(safe-area-inset-top, 0px), 28px)`.
  - В `client/src/App.tsx` добавлен защитный распорочный блок `safe-top-spacer`, динамически подключающий класс платформы `capacitor-android` и управляющий `StatusBar.setOverlaysWebView({ overlay: false })`.

#### 2. Временное скрытие входа через GitHub на экране авторизации:
- **Проблема:** Кнопка входа через GitHub занимала место на экране авторизации, в то время как основной упор сделан на Telegram и Google.
- **Исправление:**
  - В `client/src/components/AuthScreen.tsx` скрыта кнопка GitHub, социальные провайдеры переведены в аккуратную двухколоночную сетку `grid-cols-2 gap-2.5` (Telegram + Google).
  - Под ними акцентирована кнопка «Войти по 6-значному коду из Telegram».
  - Верхний переключатель темы (`ThemeSwitch`) снабжён отступом `top-[calc(var(--safe-top)+1rem)]`.

#### 3. Устранение ошибки «Недействительный PKCE code_verifier» при входе через Google в приложениях:
- **Проблема:** При авторизации через Google в Windows Desktop и Android APK на экране возникала ошибка `Недействительный PKCE code_verifier`.
- **Корневая причина:**
  1. В `server/src/routes/auth.ts` маршрут `/api/auth/native/session` деструктурировал параметры в `snake_case` (`code_challenge`, `code_challenge_method`, `redirect_uri`), в то время как клиент отправлял их в `camelCase` (`codeChallenge`, `codeChallengeMethod`, `redirectUri`). Сервер сохранял пустую строку в качестве `code_challenge`, из-за чего последующая валидация падала.
  2. Состояние гонки (Race Condition): при успешном завершении OAuth в браузере сразу три канала (WebSocket `native_auth_listen`, фоновый опрос Polling и Deep Link `pulsechat://auth/callback`) почти одновременно вызывали `/api/auth/exchange`. Первый запрос забирал токен, а второй слал уже сгоревший код авторизации, приводя к ошибке PKCE.
  3. Отсутствие безопасного фоллбэка `SubtleCrypto` в изолированных WebView окружениях.
- **Исправление:**
  - В `server/src/routes/auth.ts` добавлена поддержка обоих форматов именования полей (`camelCase` и `snake_case`).
  - В `client/src/utils/pkce.ts` реализована функция `safeExchangeAuthCode` со встроенным кэшем/замком `inFlightExchanges`, гарантирующая дедупликацию одновременных запросов обмена кода.
  - В `generateCodeChallenge` добавлен фоллбэк на метод `plain`, если криптографический API браузера недоступен.

#### 4. Персистентность загружаемых изображений и медиафайлов:
- **Проблема:** При перезапуске контейнера в Render (эфемерная файловая система) загруженные файлы из директории `/uploads` удалялись, приводя к ошибкам `404 Not Found` (битые аватарки и картинки). Кроме того, в десктопных и мобильных приложениях относительные ссылки `/uploads/...` не открывались.
- **Исправление:**
  - В `server/src/migrations/schema.ts` добавлена миграция `005_media_files_persistence`: создана таблица `media_files (filename TEXT PRIMARY KEY, mime_type TEXT NOT NULL, data BYTEA/BLOB NOT NULL, size INTEGER NOT NULL, created_at TIMESTAMPTZ)`.
  - В `server/src/routes/upload.ts` при загрузке файлов буфер бинарных данных немедленно сохраняется в БД.
  - В `server/src/index.ts` эндпоинты `/uploads/:filename` и `/api/uploads/:filename` проверяют наличие файла на диске, а при его отсутствии извлекают бинарные данные из таблицы `media_files`, восстанавливают локальный кэш на диске и отдают клиенту с заголовками `Cache-Control: public, max-age=31536000, immutable`.
  - В `client/src/config/runtime.ts` реализована универсальная функция `resolveAssetUrl(url)`, гарантирующая преобразование путей `/uploads/...` в абсолютные URL удалённого бэкенда для нативных клиентов.
  - Функция `resolveAssetUrl` интегрирована во все клиентские компоненты: `Avatar`, `ChatArea`, `ImageViewerModal`, `VoiceMessagePlayer`, `RightInfoPanel`.

#### 5. Результаты автоматизированного тестирования:
- Написан проверочный тестовый набор `scripts/test_v192_fixes.js` (18 проверок).
- Все 6 тестовых наборов `npm test` успешно пройдены (100% PASS).
- Сборка `npm run build` клиента и сервера завершена с нулевыми ошибками компиляции.
- Windows Desktop приложения `PulseChat-Setup-1.9.2.exe` и `PulseChat-Portable-1.9.2.exe` успешно собраны.

### Версия 1.9.1
**Дата:** 24 октября 2026  
**Категория:** Critical Bugfix / In-App Telegram Authentication / Desktop & Mobile Architecture  
**Статус:** Исправление запуска Windows .exe, устранение выброса в браузер, вход по 6-значному коду  

#### 1. Устранение пустого тёмно-синего экрана (#090d16) в Windows .exe:
- **Проблема:** При запуске скомпилированного приложения Windows `.exe` (NSIS Setup или Portable) открывалось пустое тёмно-синее окно без кнопок, тайтлбара и формы входа.
- **Корневая причина:** В `client/vite.config.ts` не был задан параметр `base: './'`. По умолчанию Vite генерировал `index.html` с абсолютными путями `<script src="/assets/index-xxx.js">`. Когда Electron открывал бандл через `loadFile(...)` по протоколу `file://`, пути разрешались в корень системного диска `file:///C:/assets/...`, Chromium выкидывал ошибку `net::ERR_FILE_NOT_FOUND`, и React не стартовал.
- **Исправление:**
  - В `client/vite.config.ts` установлен относительный базовый путь `base: './'`.
  - В `client/index.html` все пути к фавиконке и манифесту приведены к относительным (`./logo.svg`, `./manifest.webmanifest`).
  - В `desktop/main.cjs` добавлены обработчики событий `webContents.on('did-fail-load')` и `webContents.on('console-message')` для детальной диагностики рендерера.
  - В IPC-обработчик `open-external` добавлено разрешение протоколов `tg://` и `pulsechat://`.
  - Добавлен автоматизированный режим проверки `--test-run` в Electron. Локальный запуск подтвердил успешный рендеринг DOM, тайтлбара и экрана авторизации (`childCount: 2`, `htmlLength: 13789`, `hasTitlebar: true`, `hasAuthScreen: true`).

#### 2. Устранение выбрасывания пользователя в браузер на сайт:
- **Проблема:** При попытке авторизации через мобильное приложение Android или Windows внешняя OAuth-авторизация завершалась редиректом браузера на веб-сайт `https://pulse-chat-qel7.onrender.com/?auth=success`, оставляя пользователя в браузере вместо возврата в приложение.
- **Корневая причина:** Идентификатор `native_session` передавался только в начальном URL `/api/auth/google`, но не сохранялся в базе данных `oauth_states`. После прохождения через Google/GitHub серверный `/callback` считывал параметры и считал запрос обычным входом с веб-страницы.
- **Исправление:**
  - Добавлена миграция базы данных `004_native_session_and_telegram_login_codes`, добавившая столбец `native_session_id` в таблицу `oauth_states`, а также персистентную таблицу `native_auth_sessions`.
  - В `server/src/auth.ts` и `server/src/routes/auth.ts` сохранение `native_session_id` внедрено в функции `createOAuthState` и `consumeOAuthState`.
  - В `completeOAuthRedirect` при наличии `native_session_id` сервер обновляет сессию в PostgreSQL, отправляет токен по сокет-каналу `notifyNativeAuthSuccess` и отдаёт специальную страницу возврата с автоматическим переходом `pulsechat://auth/callback?code=...`, крупной кнопкой «Вернуться в приложение PulseChat» и кнопкой закрытия вкладки `window.close()`. Браузер больше не редиректит на сайт!

#### 3. Вход по 6-значному коду из Telegram без открытия браузера:
- **Проблема:** Необходимость открывать браузер для авторизации в нативном приложении.
- **Исправление:**
  - В Telegram-боте реализован перехват команд `/code`, `/login` и `/start`: бот генерирует 6-значный одноразовый числовой код, сохраняет его в таблицу `telegram_login_codes` (срок жизни 10 минут) и отправляет пользователю в Telegram с возможностью копирования в один клик (`<code>123 456</code>`).
  - Создан защищённый эндпоинт `POST /api/auth/telegram/code/verify` с ограничением частоты запросов, валидацией срока действия и мгновенной выдачей сессии.
  - На экран авторизации `AuthScreen.tsx` добавлена кнопка «Войти по 6-значному коду из Telegram» (бейдж «Без браузера») и модальное окно `TelegramCodeModal.tsx` с удобным вводом цифр и моментальным авто-входом.
  - В `TelegramBotModal.tsx` кнопка «Открыть Telegram» переведена на нативный протокол `tg://resolve?domain=...&start=...` с автоматическим запуском десктопного или мобильного клиента Telegram и опцией переключения на ввод 6-значного кода.

### Версия 1.9.0
**Дата:** 24 октября 2026  
**Категория:** Critical Bugfix / Feature / Native Mobile & Desktop / Architecture / CI/CD  
**Статус:** Стабильный релиз мобильной адаптации и нативных автономных приложений  

#### 1. Критическое исправление мобильной верстки (< 768px):
- **Устранена блокировка в единственном чате:**
  - В `ChatContext.tsx` при начальной загрузке на экранах `< 768px` `activeConversationId` инициализируется в `null`. Теперь при входе со смартфона пользователь сразу видит полный список диалогов (`Sidebar`), вкладки и бургер-меню, а не оказывается заперт в чате.
  - Автовыбор чата «Избранное» при отсутствии активного диалога ограничен исключительно десктопными экранами (`window.innerWidth >= 768`).
- **Адаптивная ширина боковой панели (`Sidebar.tsx`):**
  - Пользовательская ширина (`settings.sidebarWidth` от 340px до 500px) теперь применяется только на десктопе (`isDesktop ? { width: ... } : undefined`).
  - На мобильных устройствах сайдбар строго занимает 100% ширины экрана (`w-full`), исключая горизонтальное переполнение и обрезание элементов управления.
- **Удобная кнопка возврата и edge-swipe жест (`ChatArea.tsx`):**
  - Кнопка «Назад» (`ArrowLeft`) отделена от интерактивного кликабельного заголовка чата, увеличен touch-target до стандарта доступности 44×44px (`min-w-[44px] min-h-[44px]`), поднят `z-index: 30`.
  - Реализован жест свайпа от левого края экрана (`touchStartX < 40px`, `deltaX > 65px`) для естественного возврата к списку чатов одной рукой.
- **Динамическая высота вьюпорта (`100dvh`):**
  - `App.tsx` и `AuthScreen.tsx` переведены с `100vh` на `h-[100dvh]` с `max-w-full overflow-hidden`, что предотвращает выталкивание нижней панели ввода за пределы экрана адресной строкой мобильных браузеров.
  - Добавлена обработка события `popstate` для поддержки аппаратной кнопки «Назад» на Android.

#### 2. Полноценные автономные нативные приложения (Android & Windows):
- **Отказ от WebView-ярлыков:**
  - Нативные приложения для Android (`.apk`) и Windows Desktop (`.exe`) теперь полностью автономны и загружают локальный бандл интерфейса из `dist` / assets APK (`loadFile` / local webDir), а не оборачивают сайт в WebView.

**Дата:** 24 октября 2026  
**Категория:** Stable Release / Hotfix / Stability / React Rules of Hooks / Error Boundary

**Устранение критического бага: Чёрный экран через 1 секунду после входа (коммит 559a283):**

1. **Корневая причина №1 (Нарушение Rules of Hooks в `ChatArea.tsx`):**
   - **Где падало:** `client/src/components/ChatArea.tsx` (в коммите 559a283 хук `useEffect` для глобального Escape-хэндлера находился на строке **282**, НИЖЕ раннего выхода `if (!activeConversation) return (...)` на строке **174**).
   - **Механизм краша:** Сразу после входа в приложение `activeConversation` равен `null` (идёт фоновая загрузка списка чатов с `/api/conversations`). `ChatArea` отрабатывал ранний `return` со строками 174–185, выполняя только первые 15 хуков. Ровно через ~1 секунду с сервера возвращался список чатов, `activeConversation` становился непустым, и React шёл рендерить компонент дальше, натыкаясь на 16-й хук `useEffect` на строке 282. React выбрасывал фатальную ошибку: `Uncaught Error: Rendered more hooks than during the previous render`, немедленно размонтируя всё дерево компонентов в пустой чёрный экран.
   - **Исправление:** Все хуки (`useEffect`, `useState`, `useRef`) перенесены на самый верх компонента `ChatArea.tsx` (строки 73–199) строго ДО любого условного или раннего `return`.

2. **Корневая причина №2 (Падение `FormattedMessageText` на голосовых и медиа-сообщениях):**
   - **Где падало:** `client/src/components/FormattedMessageText.tsx` вызывал `.split(tokenRegex)` напрямую у пропса `text`.
   - **Механизм краша:** В чате с голосовыми сообщениями (`type: 'voice'`) поле `text` / `content` равно `null` или `undefined`. При открытии такого чата через 1 секунду после авторизации React вызывал `FormattedMessageText`, происходил `TypeError: Cannot read properties of undefined (reading 'split')`, гасивший всё приложение.
   - **Исправление:** Добавлена строгая проверка `const safeText = typeof text === 'string' ? text : ''; if (!safeText) return null;`. В `ChatArea.tsx` компонент `FormattedMessageText` вызывается только при наличии текстового содержимого.

3. **Защитные меры в `VoiceMessagePlayer.tsx` и `ThemeContext.tsx`:**
   - В `VoiceMessagePlayer.tsx`: добавлен безопасный фолбэк для `audioUrl` (`typeof audioUrl === 'string' ? audioUrl : ''`), защита в генерации волн (`safeUrl.charCodeAt`) и предотвращение попыток воспроизведения `undefined`.

   - Область переписки обёрнута в отдельный `<ErrorBoundary name="Область переписки (ChatArea)">`, гарантируя, что любая непредвиденная ошибка в переписке изолируется в блоке чата и не затрагивает левую панель и навигацию.

### Версия 1.5.0
**Дата:** 23 октября 2026  
**Категория:** Fix / Database / Data Integrity  
**Описание проблемы:**
1. Если у пользователя в базе создавалось несколько строк «Избранного», простое скрытие дубликатов в контроллере приводило к тому, что сообщения, отправленные во второй дубликат, становились недоступными.
2. Во вкладке «Группы» условие фильтрации включало каналы (`c.type === 'group' || c.isChannel`), из-за чего каналы дублировались и во вкладке «Группы», и во вкладке «Каналы».

**Решение:**
1. В `server/src/db.ts` реализована функция `healAndConsolidateSavedMessages()`:
   - Автоматически находит всех пользователей с несколькими чатами «Избранное».
   - Выбирает канонический чат (с наибольшим числом сообщений или самый ранний).
   - Перепривязывает все сообщения: `UPDATE messages SET conversation_id = <canonical_id> WHERE conversation_id = <dup_id>`.
   - Удаляет дублирующие членства и записи из таблицы `conversations`.
   - Вызывается при каждом старте сервера и при вызове `POST /api/conversations/saved`.
2. В `client/src/components/Sidebar.tsx` фильтр групп строго ограничен: `c.type === 'group' && !c.isChannel`.

**Затронутые файлы:**
- `server/src/db.ts`
- `server/src/routes/conversations.ts`
- `client/src/components/Sidebar.tsx`

**Описание проблемы и решение:**

   - Ошибки обмена токенов подробно логируются (invalid_client, redirect_uri_mismatch, invalid_grant) без утечки `client_secret` и одноразового `code`.

### Версия 1.1.0
**Дата:** 21 октября 2026  
**Категория:** Bugfix / Backend / Persistence  
**Описание проблемы:**
На облачном хостинге Render данные (пользователи, чаты, сообщения) пропадали после перезапуска сервиса, так как сервер молча откатывался на временную SQLite базу на эфемерном диске.

**Решение:**
1. В `GET /api/health` добавлены поля: `provider` ("postgres" или "sqlite"), `database_ok` (true/false), `server_epoch`.
2. Логирование при старте: выводится только тип провайдера и флаг наличия `DATABASE_URL` (задан / не задан) без вывода самого значения.
3. В продакшене (`NODE_ENV=production`) строго запрещена работа на SQLite: при отсутствии валидного `DATABASE_URL` процесс завершается с понятной ошибкой в логах (`process.exit(1)`).
4. Реализован надёжный пул подключений PostgreSQL с поддержкой PgBouncer и SSL (`rejectUnauthorized: false`).

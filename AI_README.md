## 1. Главные правила и регламент внесения изменений

Каждый раз, когда в проект вносятся любые правки:
1. **Запрет на утечку секретов**: Никогда не писать в код, тесты, README, `render.yaml` или отчёты пароли, токены, секреты API и полные строки подключения.
2. **Проверка перед коммитом**:
   - `npm run check:secrets` — проверка отсутствия секретов в коде.
   - `npm run build` — сборка клиента и сервера без ошибок.
   - `npm test` — прохождение всех автотестов.
3. **Обязательная запись в `AI_README.md`**: зафиксировать версию, дату, суть обновления или фичи, список затронутых файлов и результаты тестов.
4. **Синхронизация деплоя**: после коммита пушить в обе ветки для Render: `git push origin main` и `git push origin main:master`.

## 2. Архитектура проекта и технологический стек

- **Фронтенд (`client/`)**:
  - React 19, TypeScript, Vite, Tailwind CSS, Lucide Icons.
  - Менеджмент состояния: `ChatContext.tsx`, `ThemeContext.tsx`, `CallContext.tsx`.
  - Дизайн-токены: единая система CSS-переменных на `:root` (поверхности, текст, акцент, пузыри, радиусы, шрифты, тени, плотности).
  - UI-примитивы (`client/src/components/ui/`): `Avatar`, `Badge`, `ContextMenu`, `Modal`, `Tabs`, `Toast`, `Slider`, `ColorPicker`.
- **Бэкенд (`server/`)**:
  - Node.js, Express, TypeScript, Socket.io, Multer, `better-sqlite3` (локально) / `pg` (в облаке Render).
  - Эндпоинты: `/api/auth`, `/api/conversations`, `/api/messages`, `/api/health`, `/api/sync`.
  - Безопасность: PKCE OAuth 2.0 с хранением `state` в БД, постоянная по времени проверка `timingSafeEqual` для Telegram Webhook, безопасные cookies (`HttpOnly`, `Secure`, `SameSite=Lax`).
- **Мобильная и десктоп платформы**:
  - Capacitor Android SDK (`client/android`), PWA Manifest, Service Worker, Windows Desktop Launcher (`PulseChat-Desktop.bat` / `npm run desktop`).

### Версия 1.8.2
**Дата:** 2026-10-24  
**Категория:** Релиз / Интеграция Telegram / Автоматизация (Zero-Config Bot)  
**Статус:** Официальный релиз с нулевой конфигурацией бота (Zero-Config Telegram Integration)  
**Суть обновления:**  
Полная автоматизация авторизации через Telegram Bot API: теперь в панели Render Dashboard достаточно прописать только **одну** переменную `TELEGRAM_BOT_TOKEN`. Сервер сам определяет имя бота, регистрирует вебхук и передает корректную ссылку авторизации на клиент.

**Что сделано:**
1. **Автоопределение юзернейма бота через `getMe`:**
   - Если переменная `TELEGRAM_BOT_NAME` не задана вручную, сервер при старте и создании сессии делает вызов `https://api.telegram.org/bot<token>/getMe`, извлекает официальный `username` бота и кэширует его в памяти.
   - Клиентская модалка `TelegramBotModal` автоматически получает правильный `deepLink` (`https://t.me/<username>?start=<token>`) и отображает актуальный QR-код и кнопку перехода к боту.
2. **Алиасы переменных окружения:**
   - Поддерживаются имена `TELEGRAM_BOT_TOKEN`, `TELEGRAM_TOKEN`, `BOT_TOKEN`.
   - Поддерживаются имена `TELEGRAM_BOT_NAME`, `TELEGRAM_BOT_USERNAME`, `VITE_TELEGRAM_BOT_USERNAME`, `TELEGRAM_USERNAME`.
3. **Автоматическая регистрация вебхука:**
   - В Render автоматически используется `RENDER_EXTERNAL_URL` (или `PUBLIC_URL` / fallback).
   - Секретный токен для вебхука рассчитывается динамически через HMAC-SHA256 (`JWT_SECRET` + `TELEGRAM_BOT_TOKEN`).
   - При старте сервера метод `setupTelegramWebhook()` автоматически регистрирует вебхук в Telegram API.
4. **Улучшение UX бота в Telegram:**
   - Если пользователь отправил `/start` без токена, бот отвечает приветственным сообщением с инструкцией по входу в PulseChat.

**Затронутые файлы:**
- `server/src/routes/auth.ts` — функция `fetchTelegramBotUsername()`, авто-`getMe`, регистрация вебхука, алиасы env.
- `package.json`, `client/package.json`, `server/package.json` — версия 1.8.2.
- `CHANGELOG.md` & `AI_README.md` — документация обновления.

### Версия 1.8.1
**Дата:** 2026-10-24  
**Категория:** Stable Release / Hotfix / Стабильность / React Rules of Hooks / ErrorBoundary  
**Статус:** Стабильный релиз (Stable Production Release, git tag `v1.8.1`)  
**Суть обновления:**  
Срочное устранение критического сбоя продакшена (чёрный экран через 1 секунду после авторизации после деплоя коммита 559a283):

1. **Корневая причина №1 (Нарушение Rules of Hooks в `ChatArea.tsx`):**
   - **Где падало:** `client/src/components/ChatArea.tsx` (в коммите 559a283 хук `useEffect` для глобального Escape-хэндлера находился на строке **282**, НИЖЕ условного выхода `if (!activeConversation) return (...)` на строке **174**).
   - **Механизм краша:** Сразу после входа в приложение `activeConversation` равен `null` (идёт фоновая загрузка списка чатов с `/api/conversations`). `ChatArea` отрабатывал ранний `return` со строками 174–185, вызывая только первые 15 хуков. Ровно через ~1 секунду с сервера возвращался список чатов, `activeConversation` становился непустым, и React шёл рендерить компонент дальше, натыкаясь на 16-й хук `useEffect` на строке 282. React выбрасывал фатальную ошибку: `Uncaught Error: Rendered more hooks than during the previous render`, немедленно размонтируя всё дерево компонентов в пустой чёрный экран.
   - **Исправление:** Все хуки (`useEffect`, `useState`, `useRef`) перенесены на самый верх компонента `ChatArea.tsx` (строки 73–199) строго ДО любого условного или раннего `return`.

2. **Корневая причина №2 (Падение `FormattedMessageText` на голосовых и медиа-сообщениях):**
   - **Где падало:** `client/src/components/FormattedMessageText.tsx` вызывал `.split(tokenRegex)` напрямую у пропса `text`.
   - **Механизм краша:** В чате с голосовыми сообщениями (`type: 'voice'`) поле `text` / `content` равно `null` или `undefined`. При открытии такого чата через 1 секунду после авторизации React вызывал `FormattedMessageText`, происходил `TypeError: Cannot read properties of undefined (reading 'split')`, гасивший всё приложение.
   - **Исправление:** Добавлена строгая защита: `const safeText = typeof text === 'string' ? text : ''; if (!safeText) return null;`. В `ChatArea.tsx` компонент `FormattedMessageText` вызывается только при наличии непустого текстового содержимого.

3. **Защитные меры в `VoiceMessagePlayer.tsx` и `ThemeContext.tsx`:**
   - В `VoiceMessagePlayer.tsx`: добавлен безопасный фолбэк для `audioUrl` (`typeof audioUrl === 'string' ? audioUrl : ''`), защита в генерации волн (`safeUrl.charCodeAt`) и предотвращение создания объекта `new Audio` при отсутствии ссылки.
   - В `ThemeContext.tsx`: добавлена функция глубокой валидации и очистки `sanitizeSettings()`, защищающая от битых или неполных объектов обоев (`settings.wallpaper`) из старых версий `localStorage` (`pulse_theme_v2`).
   - В `ChatArea.tsx`: добавлена проверка `Array.isArray(msg.reactions)` перед вызовом `.reduce()`.

4. **React `ErrorBoundary` на уровне приложения и чата:**
   - Создан класс-компонент `client/src/components/ErrorBoundary.tsx` с выводом имени компонента, текста ошибки (`error.name` и `error.message`), а также кнопками «Перезагрузить» и «Сбросить кэш и перезагрузить» (очищает `localStorage` и `sessionStorage`).
   - Корневое приложение в `client/src/App.tsx` обёрнуто в `<ErrorBoundary name="Корневой интерфейс (App)">`.
   - Область переписки обёрнута в отдельный `<ErrorBoundary name="Область переписки (ChatArea)">`, гарантируя, что любая непредвиденная ошибка в переписке изолируется в блоке чата и не затрагивает сайдбар.

5. **Тестирование:**
   - Создан скрипт проверки `scripts/test_hotfix_blackscreen.js` (проверяет Rules of Hooks в AST/исходниках, безопасность `FormattedMessageText`, санитизацию тем и работу `ErrorBoundary`).
   - Все тесты пройдены: 6/6 в `test_hotfix_blackscreen.js`, 100% в `test:stages`. Пройдена компиляция TypeScript и Vite (`npm run build`).

**Затронутые файлы:**
- `client/src/components/ChatArea.tsx` — перенос хука `useEffect` наверх, защита `reactions` и `replyTo`.
- `client/src/components/FormattedMessageText.tsx` — безопасная обработка null/undefined/non-string `text`.
- `client/src/components/VoiceMessagePlayer.tsx` — защита от null/undefined `audioUrl`.
- `client/src/components/ErrorBoundary.tsx` — новый компонент предохранителя ошибок с красивым UI.
- `client/src/App.tsx` — обёртка корневого приложения и ChatArea в ErrorBoundary.
- `client/src/context/ThemeContext.tsx` — функция санитизации тем `sanitizeSettings`.
- `scripts/test_hotfix_blackscreen.js` — автоматизированные тесты хотфикса.
- `CHANGELOG.md` & `AI_README.md` — фиксация изменений и архитектурного анализа.

### Версия 1.8.0
**Дата:** 2026-10-24  
**Категория:** Релиз / Telegram UI/UX / Этапы 5, 6, 7  
**Суть обновления:**  
Завершение полного цикла переноса PulseChat на Telegram-стандарт: живое интерактивное окно настроек оформления (Live Preview), доработка Бургер-меню (Drawer) и страницы авторизации, защита от удаления системного диалога «Избранное», пересылка сообщений (Forward), анти-overlap спейсер времени внутри пузырей, кликабельные спойлеры и глобальные горячие клавиши.

**Что сделано:**
1. **Точечные исправления и безопасность Этапа 4:**
   - Вкладка «Личные» в `Sidebar.tsx`: добавлен строгий фильтр `c.type === 'direct' && !c.isSaved && !c.isChannel` для разделов и подсчёта счётчиков, исключающий чат «Избранное» из обычных личных диалогов.
   - Серверный эндпоинт `DELETE /api/conversations/:id`: добавлена проверка участника диалога (403), блокировка удаления системного чата «Избранное» (`is_saved = 1`) с кодом 400 (`Cannot delete Saved Messages conversation`). В контекстном меню «Избранного» доступно только действие «Очистить заметки».
   - В контекстное меню сообщений добавлен пункт **«Переслать» (Forward)** и компонент `ForwardModal.tsx` со списком диалогов, превью сообщения и поиском. В `ChatContext` реализован метод `forwardMessage`.
   - В пузыри текстовых сообщений внедрён Telegram-спейсер `inline-block w-14 h-3.5 select-none pointer-events-none` и плавающий time-badge `float-right -mb-1 ml-2 mt-1`, исключающий перекрытие длинного текста временем и галочками.
2. **Этап 5: Экран входа, Drawer-меню и Модалки:**
   - **Экран входа (`AuthScreen.tsx`):** полностью адаптирован под дизайн-токены Telegram (`var(--bg-app)`, `var(--bg-surface)`, `var(--border-subtle)`), интерактивный анимированный логотип, независимые состояния загрузки для кнопок OAuth (Telegram, Google, GitHub), быстрый переключатель Светлая/Тёмная тема в правом верхнем углу, вывод и закрытие понятных ошибок безопасности OAuth (`oauth_access_denied`, `oauth_state_mismatch`, `oauth_exchange_failed`). Роуты и логика `/api/auth/*` сохранены без изменений.
   - **Бургер-меню (Drawer) в `Sidebar.tsx`:** плавный выезд, кликабельная карточка профиля пользователя, пункты «Мой профиль», «Избранное», «Создать группу/канал», «Контакты», «Настройки и оформление», «Подключить телефон», анимированный тумблер ночного режима с вращением иконки и модалка подтверждения выхода на дизайн-токенах.

3. **Этап 6: Окно «Настройки → Оформление» с Live Interactive Preview:**
   - **Живой интерактивный предпросмотр (Live Preview):** верхняя панель предпросмотра с 3 демо-сообщениями (входящее от Павла Дурова, исходящее с кастомным цветом и галочками, входящее со спойлером), меняющаяся в реальном времени при движении любых ползунков и селекторов.

   - **Акцентный цвет:** быстрые пресеты + произвольный пикер `ColorPicker`.
   - **Кастомизация пузырей:** 9 вариантов заливки исходящих (включая градиенты Sunset, Cyber, Ocean) и слайдер скругления углов `--bubble-radius` от 4px до 20px.
